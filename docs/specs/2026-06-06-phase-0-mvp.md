# Spec — Phase-0 MVP (CLI runner, dry-run)

**Status:** Planned · **Date:** 2026-06-06 · **Scope:** [ADR-0019](../../decisions/0019-phase-0-mvp-scope.md) ·
**Elaborates:** [the high-level runner spec](2026-06-06-ci-action-runner.md)

Phase 0 is the smallest end-to-end slice: a **CLI** that reviews a local diff or a PR's diff
with the **Anthropic BYOK** adapter across **correctness + security**, runs Stages 2–5 in
**dry-run** (writes `findings.json` + `summary.md`, posts nothing), and reproduces the
interactive skill's verdict. No GitHub Action, no pre-filter, no posting yet (those are P1/P2).

## Goal & non-goals

**Goal:** `python3 -m runner --diff <path|--pr N> --provider anthropic --model <m> --dry-run`
produces a calibrated, schema-valid findings set whose verdict matches the interactive skill
on Lucky #1263.

**Non-goals (Phase 0):** posting to GitHub, the pre-filter (Stage 1), Ollama/OpenAI adapters,
parallel dimensions, prompt caching, path-rules. (All owned by later phases —
[roadmap](../roadmap.md).)

## CLI contract

```
python3 -m runner
  (--pr <N> | --diff <path>)        # PR number (uses gh to fetch diff) OR a local patch
  --provider anthropic              # Phase 0: anthropic only
  --model claude-sonnet-4-6         # default cost/quality; claude-opus-4-8 for max quality
  --api-key-env CODE_REVIEW_API_KEY # env var holding the key (never the key itself)
  [--repo owner/name]               # required with --pr
  [--config .code-review.yml]       # optional; flat subset only in P0
  [--severity-floor P1]             # default P1
  [--dry-run]                       # Phase 0: implied/forced — writes files, posts nothing
  [--out ./review]                  # output dir for findings.json + summary.md
  [--force-large-diff]              # bypass the budget-guard truncation
```

Exit code: `0` on success (review is **data, not a gate**); non-zero only on **infra** error
(bad key, network, malformed diff).

## Pipeline (Phase 0 runs Stages 2 → 3 → 4 → 5-dry)

- **Stage 2 — scope** ([ADR-0016](../../decisions/0016-diff-scope-and-trivial-skip-stage-2.md)):
  parse `git diff base..head` (or the `--diff` patch) into `DiffHunk`s; add **N=10** lines of
  context; collapse adjacent hunks; **trivial-skip** if total changed LOC < 50 and
  whitespace/comment/rename-only; budget-guard truncates **at hunk boundaries** above ~16K
  tokens (warn).
- **Stage 3 — LLM review** ([ADR-0017](../../decisions/0017-prompt-construction-and-structured-output-stage-3.md)):
  build one system prompt covering **correctness + security**, call the Anthropic adapter with
  **structured output**, parse to `Finding[]`. (No Stage-1 context in P0 — pre-filter is P1.)
- **Stage 4 — merge & gate** ([ADR-0018](../../decisions/0018-merge-and-confidence-gating-stage-4.md)):
  dedup by `fingerprint`, apply the ADR-0002 matrix at `severity_floor`, sort, mark
  fix-eligibility.
- **Stage 5 — dry post:** write `findings.json` (schema below) + a `summary.md` shaped like
  the skill's chat report (`## Verdict`, per-severity sections, `## What's good`,
  `## Dimensions checked`). **No GitHub calls.**

## Findings JSON schema (normative, shared by all stages/providers)

```json
{
  "schema_version": "1.0",
  "verdict": "approve | approve-with-nits | changes-required",
  "summary": "1–2 sentences on the overall change",
  "findings": [
    {
      "path": "src/api/upload.ts",
      "line": 42,
      "end_line": 44,
      "severity": "P1",
      "title": "unawaited write can lose data on crash",
      "body": "fs.writeFile is fire-and-forget; the error is swallowed and the request returns before the write completes. A crash mid-write loses user data.",
      "suggestion": "await fs.promises.writeFile(dest, buf);",
      "dimension": "correctness",
      "evidence_type": "factual",
      "confidence": 0.95,
      "source": "llm:correctness",
      "fingerprint": "src/api/upload.ts:42:unawaited-write"
    }
  ]
}
```

Constraints: `additionalProperties:false`; `severity ∈ {P0,P1,P2,P3}`;
`evidence_type ∈ {factual,behavioral,speculative}`; `confidence ∈ [0,1]`; `suggestion` only
for `factual` + small (≤ ~5 lines); `title` < 70 chars; `fingerprint = path:line:category_slug`.

## Worked dimension prompt (correctness) — the judgment-transfer pattern

The system prompt is assembled from the existing judgment layer + the **verbatim** ADR-0002
rubric; the diff is the volatile suffix. (Security uses the same shape with its own checklist.)

```
You are a senior QA/staff reviewer analyzing a PR diff through the CORRECTNESS lens.
Find code that runs and type-checks but computes the wrong thing or breaks an invariant.

## Calibration (verbatim — drives ADR-0002 gating; emit these fields)
- factual (high): off-by-one, inverted condition, null-deref, uncaught type error —
  citable at file:line with no runtime context needed. confidence > 0.7.
- behavioral (moderate): edge cases (empty/null/max/overflow), races, async ordering —
  input/timing dependent. confidence 0.5–0.7.
- speculative (low): hunches — phrase as a QUESTION, never an assertion. confidence < 0.5.

## Checklist (from REFERENCE.md#correctness)
logic matches intent; edge cases; off-by-one/boundaries; error paths return/throw;
async awaited / no floating promises / races / cancellation; idempotency; transactions.

## Patterns to recognize (advisory, from references/)
{2–3 entries selected by defect class, e.g. references/intent-implementation-mismatch.md,
 references/business-logic-edge-cases.md — interpolated verbatim, NOT retrieved via RAG}

## Already reported by deterministic tools — DO NOT re-flag  (empty in Phase 0)
{stage_1_findings}

## Diff under review
{stage_2_hunks_with_context}

## Output
Return JSON conforming to the findings schema. Tag every finding with dimension,
evidence_type, confidence. Only mark factual with a cited file:line + reason. Reframe
confidence < 0.5 as a question.
```

Structured output: Anthropic constrained decoding (P0). The shared schema is reused verbatim
for the OpenAI-compatible (JSON-schema) and Ollama (JSON-mode + retry) paths in later phases.

## Validation gate (Phase 0 "done")

1. On **Lucky #1263**, the CLI reproduces the interactive skill's **verdict**
   (`approve-with-nits`) and surfaces **zero new P0/P1/P2** findings vs the chat review
   (the pilot already established the ground truth — engine caught its own false positive,
   verified the "zero callers" claim, grounded "typecheck clean" in CI).
2. `findings.json` is **100% schema-valid** (no parse errors).
3. `summary.md` matches the skill's report shape.
4. No network calls except the LLM API (dry-run posts nothing).

## Open prerequisite (carried)

Posting (Stage 5 live) and the GitHub Action are **P2** and depend on the bot identity
([ADR-0004](../../decisions/0004-github-app-posting-identity.md)). Phase 0 is dry-run, so it
is **not** blocked.
